# Архитектура первой версии

## ADR-001: Go / WebView2 / PDF.js

Для первого рабочего приложения выбраны Go как host/controller и Microsoft Edge WebView2 как поверхность рендеринга. PDF.js 6.4.299 (Apache-2.0) поставляется внутри EXE вместе со worker, CMaps, стандартными шрифтами и WASM-декодерами. После сборки загрузок из CDN нет. Это уточнение исходного плана: сравнение PDFium/MuPDF отложено до появления измерений, которые покажут необходимость нативного PDF-движка.

Go открывает только разрешённые библиотечные файлы или явно импортированные пользователем книги. Локальный HTTP-сервер связывает два WebView2 и обслуживает embedded UI. Случайный токен позволяет получить HttpOnly/SameSite cookie. Проверяются Host, Origin и токен; PDF поддерживает HTTP Range. HTML книг очищается на Go, внешние ресурсы и активное содержимое блокируются также CSP.

## Навигация и синхронизация

`internal/reader` содержит независимую модель страниц. `internal/app` сериализует команды из обоих окон и увеличивает revision. SSE рассылает `prepare`. Каждое представление готовит страницы в невидимом контейнере и отправляет `ready` с revision и ID подключения. Только когда готовы все подключённые представления, сервер отправляет `commit`. Устаревшие подтверждения игнорируются; отключившееся представление исключается из барьера.

Это синхронная публикация состояния; WebView2 на разных дисплеях не гарантируют аппаратно синхронный vsync. При неудаче рендера остаётся последний готовый разворот, а UI показывает ошибку.

Размер страницы согласуется по меньшей доступной области подключённых представлений. PDF рисует лишь видимые страницы, до 12 мегапикселей на поверхность. PDF.js самостоятельно управляет данными документа; отдельный байтовый LRU и prefetch следующих разворотов пока не реализованы.

## Форматы

PDF читается PDF.js в каждом представлении. FB2/FB3 разбираются XML-парсером Go с ограничением глубины; FB2 binary преобразуется в локальные ресурсы, FB3 relationships связывают изображения. EPUB spine задаёт порядок глав; HTML проходит белый список тегов и атрибутов. Все потоковые форматы превращаются в HTML с CSS columns и одинаковой геометрией на обоих экранах.

ZIP проверяется на небезопасные пути, число записей, размер записи и суммарный распакованный объём. Файлы не извлекаются в произвольные пути. Пределы первой версии: 1 GiB исходный файл, 5000 записей, 32 MiB на запись, 192 MiB суммарно.

## Windows host

Каждое окно работает в отдельном OS thread с собственным COM STA и циклом сообщений. Мониторы перечисляются через EnumDisplayMonitors / GetMonitorInfoW и сортируются по числу в `DISPLAYn`; DISPLAY1 считается левым. DPI awareness задаётся до создания окон. Подкласс оконной процедуры обрабатывает WM_DISPLAYCHANGE и WM_DPICHANGED. Полноэкранные окна размещаются по физическим границам мониторов.

Книги пользователя остаются вне бинарника. Сессии сохраняются JSON-файлом через временный файл и rename в `%LocalAppData%\DuoReader`; каталог переопределяется `-data`.
